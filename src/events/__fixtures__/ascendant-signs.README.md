# Ascendant sign reference

Generated by `scripts/events/derive-ascendant.py` using pyerfa 2.0.1.5
(SOFA/ERFA `gmst82` and `obl80`). Run `npm run build`, install pyerfa in
`/tmp/erfa-venv`, then run that Python interpreter on the script.
The embedded request records TT bounds, geographic coordinates (east-positive
longitude), and Celestine's endpoint Delta T values. Only the time conversion
uses Celestine; sidereal time, obliquity, horizon geometry and boundary solving
are independent. UT1 is approximated by UT. Obliquity is evaluated on UT to
match the chart convention. `obl80` uses the same mean-obliquity cubic to the
rounding of Celestine's constants. Endpoint Delta T is linearly interpolated
across each day; these cases lie within constant/linear model segments.

The five UTC-day cases include both Berlin dates, Quito, Sydney and Reykjavik.
Polar cases are excluded because the API rejects absolute latitudes >=66°.
The test checks all 60 boundaries one-to-one with a 1 second limit, and checks
charts one second on either side. Measured maximum difference: 0.000081 seconds.

`day.test.ts` also reuses committed Horizons requests on both sides of the
first Moon and Mercury ingresses in `horizons-events.json`. No new network
response is required. Maximum true-equinox longitude differences measured on
those sides are 0.788442 arcseconds (Moon) and 0.137580 arcseconds (Mercury).
